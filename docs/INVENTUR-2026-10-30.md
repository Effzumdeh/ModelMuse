## 0. Kurzantwort auf die Kernfrage

**Ist `dist-standalone/modelmuse-standalone.html` wirklich standalone?**

**Teilweise nein.** Die Datei ist *single-file* (alle Styles, Skripte, 3D-Modelle, 2D-Engine und i18n inline), aber sie ist **nicht offline-fähig**: sie lädt 5 Ressourcen von externen CDNs (im Browser 6 Requests, weil `three.module.js` intern `three.core.js` nachlädt). Über `file://` und über HTTP verifiziert:

| Abhängigkeit | Quelle | Zweck | Kritisch? |
|---|---|---|---|
| Vue 3.5.44 | `unpkg.com/vue@3/dist/vue.global.js` | UI-Framework | **Ja** — ohne sie rendert gar nichts |
| Three.js r186 | `unpkg.com/three@0.186.1/build/three.module.js` (+ transitiv `three.core.js`) | 3D-Engine | **Ja** — ohne sie kein 3D |
| OrbitControls | `unpkg.com/three@0.186.1/examples/jsm/controls/OrbitControls.js` | Kamera-Steuerung | **Ja** für 3D |
| Tailwind CSS | `cdn.tailwindcss.com` | Styles (163 `class=`-Attribute) | **Ja** — Layout bricht ohne CSS |
| Inter Font | `fonts.googleapis.com` (+ `fonts.gstatic.com` als `preconnect`) | Typografie | Nein — Fallback auf `system-ui` |

> **Insgesamt 5 externe Domains** im Artefakt: `cdn.tailwindcss.com`, `fonts.googleapis.com`, `fonts.gstatic.com`, `unpkg.com` (3 Requests) und `inference.baseten.co` (nur zur Laufzeit, für den Baseten-BYOK-Aufruf — nicht für den Seitenaufbau).

> **Konsequenz für GitHub Pages:** Das Artefakt funktioniert auf GitHub Pages (HTTPS, Internet vorhanden) einwandfrei. Es ist aber **nicht** standalone im Sinne von „eine Datei, die ohne Netz auskommt". Wenn GitHub Pages nur eine *leichte Startseite* braucht, ist die Datei ab 378 KB einsatzbereit. Wenn *Offline-Fähigkeit* das Ziel ist, ist das Artefakt **nicht geeignet** — die Alternative ist unten (Abschnitt 3, Variante B).
